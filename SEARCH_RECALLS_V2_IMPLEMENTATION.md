
# Search Recalls V2 Implementation Summary

## Overview
This document describes the implementation of the new `search-recalls-v2` edge function and the updated search UI with a toggle to switch between text-based and image-based search.

## Edge Function: `search-recalls-v2`

### Location
`supabase/functions/search-recalls-v2/index.ts`

### Functionality
The edge function performs the following steps:

1. **Authentication**: Verifies the user's JWT token
2. **Embedding Generation**: Converts the user's search query into an embedding using OpenAI's `text-embedding-3-small` model with `base64` encoding format
3. **Vector Similarity Search**: Finds the top 8 closest matches from `recall_images.recall_image_embedding` using cosine similarity
4. **Question Answering**: Uses OpenAI's `gpt-4o-mini` model to answer questions based on the matched images' OCR text and explanations
5. **Response**: Returns the answer, confidence score (0-100), and the 8 matching recall IDs with their match percentages (sorted by highest match first)

### Request Format
```json
{
  "query": "user's search query"
}
```

### Response Format
```json
{
  "answer": "AI-generated answer based on image content",
  "confidence": 85,
  "results": [
    {
      "id": "recall-id-1",
      "matchPercentage": 95
    },
    {
      "id": "recall-id-2",
      "matchPercentage": 87
    }
    // ... up to 8 results
  ],
  "processingTimeMs": 1234
}
```

### Key Features
- Uses `text-embedding-3-small` model for cost-efficient embeddings
- Base64 encoding format for compact data transfer
- Cosine similarity calculation for finding closest matches
- Comprehensive error handling and logging
- Fallback mechanisms for robustness

## Database Function: `match_recall_images`

### Location
Created via migration: `create_match_recall_images_function`

### Purpose
PostgreSQL function to perform vector similarity search on `recall_images.recall_image_embedding` using pgvector's cosine distance operator (`<=>`).

### Parameters
- `query_embedding`: vector(1536) - The embedding to search for
- `match_threshold`: float - Minimum similarity threshold (default: 0.0)
- `match_count`: int - Number of results to return (default: 8)
- `user_id_filter`: uuid - Filter by user ID (default: NULL)

### Returns
Table with columns: `id`, `recall_id`, `ocr_text`, `image_explanation`, `distance`

## UI Changes: `app/search.tsx`

### New Features

1. **Toggle Component**: Added a Switch component to toggle between text-based (V1) and image-based (V2) search
   - Located below the search bar
   - Shows current search mode with icon and label
   - Persists selection during the session

2. **Dynamic Empty State**: Updated empty state to show different features based on selected search mode
   - Text-based search: Shows NLP, location filtering, and NER features
   - Image-based search: Shows image embedding, OCR matching, and visual analysis features

3. **Search Mode Indicator**: Visual indicator showing which search mode is active

### Updated Hook: `hooks/useNotes.ts`

Modified `searchNotes` function to accept an optional `useV2` parameter:
```typescript
searchNotes(query: string, useV2: boolean = false)
```

When `useV2` is true:
- Calls `search-recalls-v2` edge function
- Processes V2 response format
- Fetches full recall data for matched IDs
- Sorts results by match percentage
- Does not apply location filtering (V2 is image-based only)

## Search Modes Comparison

### Text-Based Search (V1 - Default)
- Uses `search-recalls` edge function
- Analyzes recall text, location, OCR text, and image explanations
- Supports location-based filtering with Google Places API
- Named entity recognition for locations
- Returns up to 10 results with relevance scores ≥75%

### Image-Based Search (V2 - New)
- Uses `search-recalls-v2` edge function
- Converts query to embedding and matches against image embeddings
- Focuses on visual content and OCR text
- Returns top 8 closest matches regardless of threshold
- No location filtering (purely content-based)

## Benefits of V2 Search

1. **Visual Content Matching**: Better at finding images with similar visual content
2. **OCR-Focused**: Prioritizes text found in images
3. **Semantic Image Search**: Can find conceptually similar images even without exact text matches
4. **Consistent Results**: Always returns top 8 matches for comparison
5. **Question Answering**: Provides AI-generated answers based on image content

## Usage

1. Navigate to the search screen
2. Toggle the switch to enable "Image-based search"
3. Enter your search query
4. View results sorted by match percentage
5. See AI-generated answer with confidence score

## Technical Notes

- Both search modes use OpenAI's GPT-4o-mini for question answering
- V2 search requires images to have embeddings (generated by `embedding-image` function)
- Cosine similarity is calculated in-memory for flexibility
- Match percentages are normalized to 0-100 range
- Empty results are handled gracefully with appropriate messaging
